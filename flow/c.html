DevOps Interview Cheat Sheet

Internal Portal → Backstage → EKS → Rafay → Terraform/OpenTofu → Helm → Kubernetes

30-Second Memory

Backstage is used as the developer/platform workflow entry point.

The onboarding workflow can provision or configure the AWS EKS environment.

Once the EKS cluster exists, Rafay can manage application environments through Environment Templates and Resource Templates.

Resource Templates can use Terraform/OpenTofu to create supporting infrastructure and application prerequisites.

Finally, Helm deploys the application into Kubernetes.

1. Internal Portal — Application Onboarding

What happens?

The developer/application team provides the information required to onboard a microservice.

Typical inputs

  • Application / microservice name
  • Repository information
  • Docker image information
  • Build/application version
  • Target environment
  • Artifact information
  • Security/scanner information when required

Conceptual flow

Developer
   ↓
Internal Portal
   ↓
Save Application Configuration
   ↓
Backstage API / Workflow
Interview wording:

"Our internal portal was used as the onboarding entry point. Application teams provided the required microservice and deployment information, and the portal triggered the Backstage workflow through an API."

2. Backstage — Workflow / Orchestration

Purpose

Backstage acts as the workflow/orchestration layer. It can automate project setup, repository configuration, templates, and infrastructure/environment workflows. 

Internal Portal
       ↓
Backstage API
       ↓
Backstage Workflow
       ↓
Project / Repository / Configuration
       ↓
Environment / Cluster Provisioning

What can the workflow perform?

  • Create project/repository structure
  • Generate YAML/configuration
  • Apply application templates
  • Create or configure Rafay project information
  • Trigger cluster/environment provisioning
Important interview distinction:

Do not say that you personally administered Backstage or EKS if the Platform team owned those functions.

A safer statement is: "I worked with the Backstage-driven workflow and used the resulting environment for application deployment."

3. AWS EKS — Cluster Provisioning

What is EKS?

Amazon EKS is AWS's managed Kubernetes service. The resulting EKS cluster is a Kubernetes cluster running on AWS.

Typical infrastructure involved

Area Typical Resources
Networking VPC, subnets, route tables
Internet connectivity Internet Gateway, NAT Gateway
Security Security Groups
Identity IAM roles and policies
Encryption KMS
Kubernetes EKS control plane
Compute Managed node groups / EC2 worker nodes
Add-ons VPC CNI, CoreDNS, kube-proxy, EBS CSI, etc.

Conceptual architecture

AWS
│
├── VPC
│
├── Public / Private Subnets
│
├── Route Tables
│
├── NAT / Internet Gateway
│
├── Security Groups
│
├── IAM
│
├── KMS
│
└── EKS
     │
     ├── Control Plane
     │
     └── Node Groups
           │
           └── EC2 Worker Nodes
Important:

The exact resources created by an enterprise EKS workflow depend on the organization's templates and whether networking/infrastructure already exists.

Do not claim that every EKS deployment creates all of these resources.

Useful Kubernetes commands

kubectl get nodes

kubectl get namespaces

kubectl get pods -A

kubectl get deployments -A

kubectl get services -A
Interview wording:

"At the platform level, the Backstage workflow was used to provision the EKS environment. My focus was primarily on the application delivery and deployment workflows running against that environment."

4. Rafay — Project → Environment Template → Agent

Important concept

At this stage, the EKS cluster already exists. Rafay is then used to manage the application environment and supporting resources. 

EKS Cluster Already Exists
          ↓
     Rafay Project
          ↓
 Environment Template
          ↓
    Launch Environment
          ↓
      Rafay Agent
          ↓
   Resource Templates

Rafay Project

A logical boundary used to organize resources, environments, applications, and related configuration.

Environment Template

An Environment Template defines the components required to create an application environment.

Agent

The Rafay agent participates in executing environment activities against the target environment.

Interview wording:

"After the EKS cluster was available, we used Rafay to launch the application environment. The Environment Template referenced the required Resource Templates, which were executed through the Rafay workflow."

5. Rafay Resource Templates → Terraform / OpenTofu

What is a Resource Template?

Think of a Resource Template as a reusable infrastructure building block used by an environment. 

Environment Template
        ↓
Resource Template
        ↓
Terraform / OpenTofu
        ↓
AWS / External Resource

Typical application prerequisites

Resource Possible Purpose
S3 Application storage / artifacts / configuration
IAM Role Application permissions
IAM Policy Fine-grained permissions
Vault Integration Secret management
RSA / SSH Configuration Authentication / secure access
Other prerequisites Resources required by the application

Example Terraform concept

# Example only.
# Actual enterprise code may be stored in Git and referenced
# by the Rafay Resource Template.

resource "aws_s3_bucket" "application_bucket" {

  bucket = "my-application-example"

  tags = {
    Application = "my-application"
    Environment = "dev"
  }
}

Execution UI

During Resource Template execution, the UI can show information such as:

  • Execution status
  • Input values
  • Output values
  • Execution logs
  • Resource status
  • Errors when execution fails
Important distinction:

The execution screen showing logs and input/output values does not necessarily mean the complete Terraform source code is displayed there. The IaC source is generally associated with the Resource Template / Git repository.

Interview wording:

"The Rafay Environment Template referenced reusable Resource Templates. Those Resource Templates used infrastructure-as-code such as Terraform or OpenTofu to provision application prerequisites. I monitored the execution status, inputs, outputs, and logs and coordinated with the platform team for platform-level issues."

6. Helm → Kubernetes Application Deployment

What is Helm?

Helm is a package manager and templating mechanism commonly used to deploy Kubernetes applications.

Basic deployment flow

Helm
  ↓
Namespace
  ↓
Deployment
  ↓
ReplicaSet
  ↓
Pod
  ↓
Container
  ↓
Docker Image

Other Kubernetes objects commonly involved

  • Service
  • ConfigMap
  • Secret / Secret reference
  • ServiceAccount
  • Ingress
  • VirtualService / Gateway
  • HPA
  • NetworkPolicy
  • PVC / PV when persistent storage is required

Example Helm commands

helm list -A

helm status my-application -n my-namespace

helm upgrade --install my-application ./chart \
  --namespace my-namespace \
  --create-namespace
Note:

The exact Kubernetes objects created by Helm depend on the chart. Not every application needs HPA, Ingress, NetworkPolicy, PVC, etc.

7. Kubernetes — What Actually Runs

Deployment → ReplicaSet → Pod → Container

Deployment
     ↓
ReplicaSet
     ↓
Pod
     ↓
Container
     ↓
Docker Image

Deployment

Defines the desired state of the application and manages ReplicaSets.

ReplicaSet

Maintains the requested number of Pod replicas.

Pod

The smallest deployable Kubernetes unit. A Pod contains one or more containers.

Container

Runs the application process from the container image.

Service

Provides a stable network endpoint for accessing Pods.

ConfigMap

Stores non-sensitive configuration.

Secret

Stores sensitive configuration or references to sensitive data.

9. Common Interview Questions & Answers

Q: What is the difference between Kubernetes and EKS?

Answer: Kubernetes is the container orchestration platform. EKS is AWS's managed Kubernetes service.

Q: Does Rafay create the EKS cluster?

Answer: It depends on the organization's workflow. In the workflow being described here, the EKS cluster is provisioned first, and Rafay is then used for application environment provisioning.

Q: What does a Rafay Resource Template do?

Answer: It provides a reusable resource/infrastructure building block that can be executed as part of an Environment Template. It can use infrastructure-as-code such as Terraform or OpenTofu.

Q: What does Helm do?

Answer: Helm packages and templates Kubernetes application resources and helps deploy or upgrade those resources consistently.

Q: Where does Terraform fit?

Answer: Terraform or OpenTofu can be used by Resource Templates to provision supporting infrastructure and application prerequisites.

Q: What happens after the prerequisites are ready?

Answer: The application deployment workflow uses Helm to create or update the required Kubernetes resources, resulting in Pods running the application container.

Q: What did you personally own?

"I worked primarily on the application delivery and CI/CD side. The platform team handled platform-level AWS and Kubernetes administration. I worked with the workflows that deployed applications into the EKS/Kubernetes environment and coordinated with the platform team when platform-level issues occurred."
