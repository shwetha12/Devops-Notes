DevOps Engineer — Technical Interview Questions & Answers

GitLab CI/CD

  • Q: What is GitLab CI/CD?
    A: GitLab CI/CD automates the software delivery process. Code changes trigger pipelines containing stages such as build, test, security scanning, packaging, and deployment.
  • Q: What is .gitlab-ci.yml?
    A: It is the configuration file that defines GitLab pipeline stages, jobs, scripts, variables, artifacts, and deployment rules.
  • Q: What are stages and jobs in GitLab?
    A: A stage represents a phase such as build, test, or deploy. A job is an individual task executed within a stage.
  • Q: What is a GitLab Runner?
    A: A GitLab Runner is the execution agent that runs CI/CD jobs.
  • Q: How would you design a GitLab pipeline for AWS?
    A: Git → Build → Test → Security Scan → Docker Build → ECR → Terraform Plan → Approval → Terraform Apply/Deploy → Validation → CloudWatch monitoring.
  • Q: How do you prevent automatic production deployment?
    A: Use protected branches/environments and manual approval for production deployment.
  • Q: How do you manage AWS credentials in GitLab?
    A: Prefer short-lived credentials using OIDC and IAM roles instead of long-lived access keys.
  • Q: How do you troubleshoot a GitLab pipeline failure?
    A: Check the failed job logs, identify the failing command, verify variables and secrets, check the runner environment, permissions, networking, and reproduce the issue when possible.
  • Q: What is a GitLab artifact?
    A: An artifact is a file generated by a job and retained for later jobs or users, such as a build package, report, or Terraform plan.
  • Q: Cache vs artifact?
    A: Cache speeds up repeated jobs by reusing dependencies. Artifacts are outputs that are passed between stages or retained.
  • Q: How do you implement branch-based deployment?
    A: Feature branches can deploy to development, release/main branches can promote to higher environments, and production can require approval.

Terraform

  • Q: What is Terraform?
    A: Terraform is an Infrastructure-as-Code tool used to define and manage infrastructure declaratively.
  • Q: What is Infrastructure as Code?
    A: Infrastructure is defined in version-controlled configuration instead of being manually created.
  • Q: What is Terraform state?
    A: Terraform state records the resources Terraform manages and maps configuration to real infrastructure.
  • Q: Where would you store Terraform state in AWS?
    A: Commonly in an encrypted S3 backend with appropriate access controls and state locking.
  • Q: Why should Terraform state not be stored in Git?
    A: State can contain sensitive information and concurrent changes can cause conflicts.
  • Q: What does terraform init do?
    A: It initializes the working directory, downloads providers and modules, and configures the backend.
  • Q: What does terraform plan do?
    A: It shows the infrastructure changes Terraform intends to make without applying them.
  • Q: What does terraform apply do?
    A: It executes the planned infrastructure changes.
  • Q: What is a Terraform provider?
    A: A provider allows Terraform to communicate with APIs such as AWS.
  • Q: What is a Terraform module?
    A: A reusable collection of Terraform resources and configuration.
  • Q: Why use Terraform modules?
    A: They provide reusable and standardized infrastructure patterns.
  • Q: What is the difference between count and for_each?
    A: count creates resources based on a number, while for_each is useful for resources identified by stable keys.
  • Q: What is Terraform drift?
    A: Drift occurs when infrastructure changes outside Terraform and no longer matches the Terraform configuration.
  • Q: How do you detect Terraform drift?
    A: Run terraform plan and investigate the differences.
  • Q: What would you do if terraform plan wants to delete production resources?
    A: Do not apply. Investigate state, configuration, variables, provider versions, imports, and manual changes first.
  • Q: How do you import an existing AWS resource?
    A: Define the Terraform resource and use terraform import to associate the existing resource with Terraform state.
  • Q: What happens if Terraform state is deleted?
    A: Terraform loses its knowledge of managed resources. Restore the state from the remote backend or import the resources again.
  • Q: What is depends_on?
    A: It explicitly tells Terraform that one resource depends on another.
  • Q: How would you manage Dev, QA, and Prod?
    A: Use reusable modules with environment-specific variables and separate state/backends or accounts where appropriate.
  • Q: How do you run Terraform from GitLab?
    A: terraform init → validate → plan → store plan artifact → approval → apply.

AWS ECS / Fargate

  • Q: What is ECS?
    A: Amazon Elastic Container Service is AWS's managed container orchestration service.
  • Q: What is Fargate?
    A: Fargate is a serverless compute engine for ECS where AWS manages the underlying servers.
  • Q: ECS EC2 vs Fargate?
    A: ECS EC2 requires management of EC2 capacity. Fargate removes that server-management responsibility.
  • Q: What is ECR?
    A: Amazon Elastic Container Registry stores Docker/container images.
  • Q: What is an ECS task definition?
    A: It defines how a container runs, including image, CPU, memory, ports, environment variables, IAM roles, and logging.
  • Q: What is an ECS service?
    A: It maintains the desired number of running tasks and replaces unhealthy tasks.
  • Q: How would you deploy a Docker application to ECS Fargate?
    A: Build the image → test → push to ECR → update the task definition → deploy the ECS service → validate the tasks → monitor with CloudWatch.
  • Q: Why use an ALB with ECS Fargate?
    A: It provides HTTP/HTTPS routing, health checks, and load balancing for ECS tasks.
  • Q: What happens if an ECS task keeps stopping?
    A: Check the stopped-task reason, container exit code, CloudWatch logs, CPU/memory, IAM, image availability, networking, and health checks.
  • Q: ECS cannot pull an image from ECR. What do you check?
    A: Check the task execution role, ECR permissions, networking, NAT/VPC endpoints, repository, image tag, and authentication.
  • Q: ALB shows unhealthy ECS targets. What do you check?
    A: Check the application port, container port, target group, security groups, health-check path, and application startup.
  • Q: What is blue/green deployment?
    A: Run the new version separately, validate it, and then shift traffic from the existing version to the new version.

AWS Lambda

  • Q: What is AWS Lambda?
    A: A serverless compute service that runs code in response to events without managing servers.
  • Q: What can trigger Lambda?
    A: API Gateway, S3, EventBridge, SQS, SNS, scheduled events, and other AWS services.
  • Q: How does Lambda scale?
    A: AWS creates additional execution environments as concurrent requests increase, subject to concurrency limits.
  • Q: What is a Lambda cold start?
    A: The initialization delay when AWS creates a new execution environment.
  • Q: How can you reduce Lambda cold starts?
    A: Optimize startup code and package size and use provisioned concurrency when appropriate.
  • Q: What is Lambda concurrency?
    A: The number of Lambda executions running simultaneously.
  • Q: Reserved vs provisioned concurrency?
    A: Reserved concurrency controls/reserves capacity. Provisioned concurrency keeps execution environments initialized to reduce cold starts.
  • Q: How do you deploy Lambda through CI/CD?
    A: Build and test → package → deploy a new version → validate → optionally shift traffic using an alias or canary strategy.
  • Q: Lambda needs access to S3. What do you configure?
    A: Give the Lambda execution role only the required S3 permissions.
  • Q: Lambda needs access to a private resource. What do you check?
    A: VPC configuration, subnets, security groups, routing/NAT or VPC endpoints, DNS, and IAM permissions.

SQS

  • Q: What is SQS?
    A: A managed message queue used to decouple producers and consumers.
  • Q: Why use SQS?
    A: It absorbs traffic spikes, decouples services, supports asynchronous processing, and improves resilience.
  • Q: Standard vs FIFO SQS?
    A: Standard provides high throughput with at-least-once delivery. FIFO provides ordering and deduplication features.
  • Q: What is visibility timeout?
    A: After a consumer receives a message, it becomes temporarily invisible to other consumers while processing occurs.
  • Q: What is a DLQ?
    A: A Dead Letter Queue stores messages that repeatedly fail processing.

SNS

  • Q: What is SNS?
    A: A publish/subscribe notification service.
  • Q: SNS vs SQS?
    A: SNS pushes messages to subscribers, while SQS stores messages for consumers to process.
  • Q: Can SNS send messages to SQS?
    A: Yes. SNS can fan out messages to multiple SQS queues.
  • Q: Why use SNS and SQS together?
    A: SNS provides fan-out while SQS provides durable asynchronous processing.

EventBridge

  • Q: What is EventBridge?
    A: A serverless event bus used to route events between AWS services and applications.
  • Q: EventBridge vs SNS?
    A: SNS is primarily pub/sub messaging, while EventBridge provides event buses, rules, event patterns, and event routing.
  • Q: Give an EventBridge example.
    A: AWS event → EventBridge rule → Lambda, SQS, or Step Functions.
  • Q: How would you schedule an AWS process?
    A: Use EventBridge Scheduler or rules to invoke a supported target.

CloudWatch

  • Q: What is CloudWatch?
    A: AWS monitoring and observability service for metrics, logs, alarms, dashboards, and events.
  • Q: What would you monitor for ECS?
    A: CPU, memory, task count, service health, deployment status, application logs, ALB metrics, latency, and HTTP errors.
  • Q: What would you monitor for Lambda?
    A: Invocations, errors, duration, throttles, concurrency, and logs.
  • Q: EC2 CPU is 95%. How do you troubleshoot?
    A: Check CloudWatch metrics, identify when it started, inspect application/process activity, review logs and traffic, and determine whether scaling or application optimization is required.
  • Q: What is a CloudWatch alarm?
    A: It monitors a metric against a threshold and can trigger an action or notification.

AWS Batch

  • Q: What is AWS Batch?
    A: A managed service for running batch computing workloads.
  • Q: When would you use Batch instead of Lambda?
    A: For longer-running, compute-intensive, or resource-intensive workloads that do not fit Lambda's execution model.
  • Q: How does AWS Batch work?
    A: Jobs are submitted to a queue and scheduled according to priority and available resources.
  • Q: What would you troubleshoot if a Batch job remains RUNNABLE?
    A: Check compute environment capacity, IAM, networking, job requirements, queue configuration, and resource constraints.

Amazon EMR

  • Q: What is Amazon EMR?
    A: A managed big-data platform commonly used for Spark and Hadoop workloads.
  • Q: When would you use EMR?
    A: For large-scale data processing and analytics workloads.
  • Q: EMR vs AWS Batch?
    A: EMR is optimized for big-data frameworks and analytics. Batch is designed for general batch computing.
  • Q: What would you check if an EMR job fails?
    A: Check step logs, cluster status, IAM roles, S3 access, application configuration, resources, networking, and Spark/Hadoop errors.

IAM

  • Q: What is IAM?
    A: AWS Identity and Access Management controls authentication and authorization.
  • Q: IAM user vs IAM role?
    A: A user is a long-term identity. A role is assumed by users or services and provides temporary credentials.
  • Q: What is least privilege?
    A: Give an identity only the permissions required to perform its function.
  • Q: ECS task role vs execution role?
    A: The execution role allows ECS to perform tasks such as pulling images and writing logs. The task role gives the application permissions to access AWS resources.
  • Q: Why is IAM important in CI/CD?
    A: Pipelines require AWS permissions, but those permissions should be tightly scoped to reduce security risk.

VPC / Networking

  • Q: What is a VPC?
    A: A logically isolated network in AWS.
  • Q: Public vs private subnet?
    A: A public subnet has a route to an Internet Gateway. A private subnet does not have a direct route to the Internet Gateway.
  • Q: Why put ECS tasks in private subnets?
    A: To reduce direct Internet exposure while allowing controlled outbound access.
  • Q: What is an Internet Gateway?
    A: It provides connectivity between a VPC and the Internet.
  • Q: What is a NAT Gateway?
    A: It allows resources in private subnets to initiate outbound Internet connections.
  • Q: Security Group vs NACL?
    A: Security groups are stateful and attached to resources. NACLs are stateless and operate at the subnet level.
  • Q: ECS application cannot reach an external service. What do you check?
    A: Route table, NAT Gateway, subnet, security group, NACL, DNS, VPC endpoints, and application configuration.
  • Q: ALB cannot reach an ECS application. What do you check?
    A: Target group, listener, container port, security groups, health check, application binding, and routing.

S3

  • Q: What is S3 used for in DevOps?
    A: Artifacts, backups, Terraform state, logs, data files, and application assets.
  • Q: How do you secure an S3 bucket?
    A: Block public access, use IAM and bucket policies, encryption, versioning, logging, and least privilege.
  • Q: Why enable S3 versioning?
    A: To retain previous object versions and recover from accidental modification or deletion.

Terraform + AWS

  • Q: Design Terraform for an ECS application.
    A: Use reusable modules for VPC, security groups, ECR, ECS cluster, task definition, ECS service, ALB, and CloudWatch.
  • Q: What would Terraform create for an ECS Fargate application?
    A: VPC, subnets, routes, security groups, ECR, ECS cluster, IAM roles, task definition, ECS service, ALB, target groups, listeners, and CloudWatch logs.
  • Q: How would you deploy Lambda using Terraform?
    A: Terraform can create the Lambda function, IAM role, permissions, environment configuration, triggers, aliases, and supporting resources.
  • Q: How would you create SQS-triggered Lambda?
    A: Create the SQS queue, Lambda function, IAM permissions, and Lambda event-source mapping.
  • Q: How would you create EventBridge → Lambda?
    A: Create the EventBridge rule, Lambda target, and Lambda permission allowing EventBridge to invoke Lambda.

Python

  • Q: How is Python used in DevOps?
    A: For automation, AWS API interaction, file processing, deployment utilities, validation, log processing, and operational scripts.
  • Q: What is Boto3?
    A: AWS's Python SDK used to interact programmatically with AWS services.
  • Q: Terraform vs Python/Boto3?
    A: Terraform is declarative IaC designed to manage infrastructure state. Boto3 directly calls AWS APIs and is useful for custom automation.
  • Q: How do you handle exceptions in Python automation?
    A: Use try/except, log meaningful errors, return appropriate exit codes, and avoid silently ignoring failures.

SDLC / Release Management

  • Q: Explain SDLC.
    A: Requirements → development → build → testing → security/quality validation → deployment → monitoring → maintenance.
  • Q: What is CI?
    A: Frequently integrating code changes and automatically building and testing them.
  • Q: What is CD?
    A: Automating delivery or deployment of validated changes to environments.
  • Q: What is release management?
    A: Planning, coordinating, approving, deploying, validating, and tracking software releases.
  • Q: What is rollback?
    A: Returning an application to a previously known-good version after a failed deployment.
  • Q: What is canary deployment?
    A: Releasing a new version to a small percentage of traffic first and progressively increasing traffic after validation.

Cloud Migration / Modernization

  • Q: How would you approach migrating a legacy application to AWS?
    A: Understand dependencies → identify requirements → design target architecture → provision infrastructure → migrate/refactor → establish CI/CD → migrate data → test → cut over → monitor → decommission legacy components.
  • Q: How do you determine whether an application should use ECS or Lambda?
    A: Evaluate runtime duration, workload pattern, scaling, container requirements, architecture, and execution limitations.
  • Q: How would you migrate with minimal downtime?
    A: Build and validate the target environment, synchronize data, deploy the new application, perform controlled cutover, monitor, and retain rollback capability.
  • Q: What dependencies do you identify before migration?
    A: Databases, APIs, queues, file systems, DNS, authentication, certificates, scheduled jobs, external systems, network connectivity, secrets, and batch processes.
  • Q: How do you validate a migrated application?
    A: Functional tests, integration tests, performance tests, security checks, data validation, deployment validation, and monitoring validation.
  • Q: How would you safely decommission a legacy application?
    A: Confirm consumers have migrated, verify dependencies and traffic are gone, archive required data, document the final state, remove infrastructure, and monitor for unexpected dependencies.

Troubleshooting

  • Q: GitLab pipeline suddenly fails. What do you do?
    A: Identify the first failing stage, inspect logs, determine whether it is code, runner, dependency, credential, network, or environment related, reproduce, fix, and rerun.
  • Q: Terraform plan shows unexpected changes. What do you do?
    A: Stop deployment and compare configuration, state, actual AWS resources, variables, provider versions, and recent manual changes.
  • Q: ECS service has zero healthy tasks. What do you check?
    A: Task status, stopped reason, CloudWatch logs, image pull, IAM, networking, container port, health checks, and CPU/memory.
  • Q: Lambda returns 500 errors. What do you check?
    A: CloudWatch logs, exceptions, IAM, networking, dependencies, input data, and application code.
  • Q: Lambda is being throttled. What do you check?
    A: Concurrency metrics and limits, invocation spikes, downstream capacity, reserved concurrency, and buffering options such as SQS.
  • Q: SQS queue keeps growing. What do you check?
    A: Consumer failures, consumer concurrency, processing duration, visibility timeout, DLQ, and downstream dependencies.
  • Q: EventBridge event is not triggering Lambda. What do you check?
    A: Event pattern, event bus, rule state, target, Lambda permission, and EventBridge logs.
  • Q: AWS Batch jobs remain pending. What do you check?
    A: Compute environment, capacity, job queue, job requirements, IAM, networking, and resource constraints.
  • Q: EMR job fails halfway through. What do you check?
    A: Spark/Hadoop logs, executor memory, S3 permissions, cluster resources, application code, and configuration.
  • Q: Application is deployed but users receive 503. What do you check?
    A: ALB target health, ECS tasks, listener, target group, container port, health checks, security groups, and application logs.

Security / DevSecOps

  • Q: Where would you put security scanning in the pipeline?
    A: Before deployment, including code quality, SAST, dependency scanning, container scanning, and IaC scanning where applicable.
  • Q: What is SAST?
    A: Static Application Security Testing analyzes source code without executing the application.
  • Q: What is DAST?
    A: Dynamic Application Security Testing tests a running application.
  • Q: How do you prevent secrets from entering Git?
    A: Use secret managers, protected CI variables, secret scanning, pre-commit checks, and never hardcode credentials.
  • Q: How would you secure an AWS CI/CD pipeline?
    A: Use least-privilege IAM, short-lived credentials, protected branches, approvals, encrypted artifacts, secret management, audit logging, and security scanning.

SAS / Jupyter / SageMaker

  • Q: What is SAS?
    A: A platform widely used for analytics, statistical analysis, reporting, and data processing.
  • Q: What is SAS Grid?
    A: A distributed environment that allows SAS workloads to run across multiple compute resources.
  • Q: What is Jupyter Notebook?
    A: An interactive environment commonly used for Python and data science experimentation.
  • Q: What is SageMaker?
    A: AWS's managed machine-learning platform for developing, training, deploying, and monitoring ML models.
  • Q: How could SageMaker fit into a DevOps workflow?
    A: Repository → testing → infrastructure provisioning → training → model validation → deployment → monitoring.
