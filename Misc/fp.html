AWS Cloud Deployment & CloudFormation Interview Guide

Purpose: Understand how AWS resources are provisioned with CloudFormation, how application deployment works, and what happens at runtime when a request, event, or job reaches the AWS service.

1. Overall Infrastructure Provisioning Pipeline

Application / Infrastructure Requirements → Git Repository → UrbanCode Provisioning Pipeline → CloudFormation → AWS Resources → Infrastructure Ready

How it works

  • Infrastructure definitions are maintained as CloudFormation YAML/JSON templates.
  • The provisioning pipeline retrieves the CloudFormation template from source control.
  • CloudFormation validates the template and creates or updates the required AWS resources.
  • CloudFormation manages dependencies between resources.
  • Once the stack finishes successfully, the environment is ready for application deployment.

2. Overall Application Deployment Pipeline

Developer Commit → Source Control → UrbanCode Deployment Pipeline → Build → Unit Tests → SonarQube → Fortify → FOSS → Package / Docker Image → ECR / Artifact Repository → AWS Deployment → Health Check → CloudWatch

Important distinction

  • Provisioning: Creates the AWS infrastructure required by the application.
  • Deployment: Places the application code/container into that already-provisioned infrastructure.

4. Amazon ECR

What is ECR? When is it used? How does it work?

Amazon Elastic Container Registry (ECR) is a managed private container registry used to store Docker/container images. It is commonly used when an application is packaged as a Docker image. ECS/Fargate, AWS Batch and other container services can pull the image from ECR when starting a container.
Dockerfile → Docker Build → Docker Image → ECR Repository → Image Tag → ECS / Batch pulls image

CloudFormation Provisioning

CloudFormation creates the ECR repository before application deployment. The repository provides a controlled location where the application container image can be stored.

The deployment pipeline later builds the Docker image and pushes it into this repository. The runtime service then references the image URI. 

AWSTemplateFormatVersion: '2010-09-09'

Resources:

  # Private ECR repository for application container images
  ApplicationRepository:
    Type: AWS::ECR::Repository

    Properties:
      RepositoryName: my-application

      # Scan images when they are pushed
      ImageScanningConfiguration:
        ScanOnPush: true

      # Keep repository contents protected
      EncryptionConfiguration:
        EncryptionType: AES256

      # Delete repository contents when stack is deleted
      EmptyOnDelete: true

What happens after deployment?

Developer Commit → Build Docker Image → Tag Image → Push Image to ECR → ECS/Batch references Image URI → Container Runtime Pulls Image

For ECS/Fargate, the ECS task definition contains the ECR image URI. When a new Fargate task starts, the task execution role allows the task to authenticate to ECR and pull the image.

For AWS Batch, the job definition normally contains the container image. When Batch starts the job, the underlying compute environment launches the container using that image.

Troubleshooting

  • Image does not exist in ECR.
  • Incorrect image tag.
  • Incorrect AWS account or region.
  • Task execution role does not have ECR permissions.
  • Network connectivity prevents image pull.

5. Amazon ECS with Fargate

What is ECS/Fargate? When is it used? How does it work?

ECS is AWS's container orchestration service. It manages containerized applications. Fargate is the serverless compute option for ECS. With Fargate, AWS manages the underlying servers while the application team defines CPU, memory, networking and container configuration.
Docker Image → ECR → ECS Task Definition → ECS Service → Fargate Task → Container

CloudFormation Resources Required

Resource Why it is required
ECS Cluster Logical grouping where ECS services/tasks run.
Task Definition Defines container image, CPU, memory, ports, environment variables and logging.
ECS Service Maintains the desired number of running tasks.
IAM Task Execution Role Allows ECS/Fargate to pull images and send logs to CloudWatch.
VPC Provides network isolation.
Private Subnets Provide network locations for Fargate tasks.
Security Group Controls inbound and outbound traffic.
CloudWatch Log Group Stores application/container logs.
ALB Receives HTTP/HTTPS requests and distributes traffic to healthy tasks.

CloudFormation Example

Resources:

  # ECS cluster
  ECSCluster:
    Type: AWS::ECS::Cluster
    Properties:
      ClusterName: my-application-cluster


  # CloudWatch log group for container logs
  ApplicationLogGroup:
    Type: AWS::Logs::LogGroup
    Properties:
      LogGroupName: /ecs/my-application
      RetentionInDays: 30


  # IAM role used by ECS/Fargate to pull images
  # and send logs to CloudWatch
  ECSTaskExecutionRole:
    Type: AWS::IAM::Role

    Properties:
      AssumeRolePolicyDocument:
        Version: '2012-10-17'

        Statement:
          - Effect: Allow
            Principal:
              Service:
                - ecs-tasks.amazonaws.com

            Action:
              - sts:AssumeRole

      ManagedPolicyArns:
        - arn:aws:iam::aws:policy/service-role/AmazonECSTaskExecutionRolePolicy


  # Defines how the container should run
  ApplicationTaskDefinition:
    Type: AWS::ECS::TaskDefinition

    Properties:

      Family: my-application

      NetworkMode: awsvpc

      RequiresCompatibilities:
        - FARGATE

      Cpu: '512'
      Memory: '1024'

      ExecutionRoleArn:
        Fn::GetAtt:
          - ECSTaskExecutionRole
          - Arn

      ContainerDefinitions:

        - Name: application

          # Image normally comes from ECR
          Image: 123456789012.dkr.ecr.us-east-1.amazonaws.com/my-application:latest

          Essential: true

          PortMappings:
            - ContainerPort: 8080

          LogConfiguration:
            LogDriver: awslogs

            Options:
              awslogs-group: /ecs/my-application
              awslogs-region: us-east-1
              awslogs-stream-prefix: application

What happens when an HTTP request comes?

User → DNS → Load Balancer → Target Group → ECS Service → Healthy Fargate Task → Container → Application Response → Load Balancer → User

The Application Load Balancer receives the HTTP/HTTPS request. The ALB checks the target group and sends traffic to a healthy Fargate task.

The request reaches the application's container port. The application processes the request and sends the response back through the ALB to the client.

Container logs are written to CloudWatch. ECS maintains the desired number of tasks defined in the service.

What happens during a new deployment?

New Code → Docker Build → ECR → New Task Definition Revision → ECS Service Update → New Fargate Tasks → Health Check → Traffic → Old Tasks Removed

Troubleshooting

  • Task stuck in PENDING.
  • Task stops immediately.
  • Cannot pull image from ECR.
  • Incorrect task role or execution role.
  • Security group blocks traffic.
  • Target group health check fails.
  • Incorrect container port.
  • Insufficient CPU or memory.
  • Application starts but immediately exits.

6. AWS Lambda

What is Lambda? When is it used? How does it work?

AWS Lambda is a serverless compute service used to execute code without managing servers. It is commonly used for event-driven processing, APIs, scheduled jobs, file processing, automation and lightweight backend operations. AWS automatically creates the execution environment when the function is invoked and manages scaling.
Event → Lambda → Execution Environment → Function Code → Response

CloudFormation Resources Required

Resource Purpose
Lambda Function Contains the application code and runtime configuration.
IAM Execution Role Defines what AWS resources the Lambda function can access.
CloudWatch Log Group Stores Lambda execution logs.
API Gateway Can expose Lambda through an HTTP/REST API.
SQS/EventBridge/S3 Can act as event sources that trigger Lambda.

CloudFormation Example

Resources:

  LambdaExecutionRole:
    Type: AWS::IAM::Role

    Properties:

      AssumeRolePolicyDocument:
        Version: '2012-10-17'

        Statement:
          - Effect: Allow

            Principal:
              Service:
                - lambda.amazonaws.com

            Action:
              - sts:AssumeRole

      ManagedPolicyArns:
        - arn:aws:iam::aws:policy/service-role/AWSLambdaBasicExecutionRole


  ApplicationFunction:
    Type: AWS::Lambda::Function

    Properties:

      FunctionName: my-application-function

      Runtime: python3.12

      Handler: lambda_function.lambda_handler

      Role:
        Fn::GetAtt:
          - LambdaExecutionRole
          - Arn

      Code:
        ZipFile: |
          def lambda_handler(event, context):
              return {
                  "statusCode": 200,
                  "body": "Hello from Lambda"
              }


  LambdaLogGroup:
    Type: AWS::Logs::LogGroup

    Properties:
      LogGroupName:
        /aws/lambda/my-application-function

      RetentionInDays: 30

What happens when Lambda is invoked?

API / S3 / SQS / EventBridge / Schedule → Lambda Invocation → Lambda Execution Environment → Python/Java/Node/etc. Code → AWS Service Calls → Response → CloudWatch Logs

For example, if an S3 object is uploaded, an S3 event can invoke Lambda. Lambda receives the event information and executes the function.

Lambda can then read the object from S3, process it, write data to DynamoDB, send an SQS message, or invoke another AWS service depending on its IAM permissions.

Troubleshooting

  • Lambda timeout.
  • Insufficient IAM permissions.
  • Incorrect handler.
  • Missing environment variable.
  • Package/dependency problem.
  • Incorrect event format.
  • Concurrency/throttling issues.
  • VPC networking problems.

7. Amazon SQS

What is SQS? When is it used? How does it work?

Amazon SQS is a managed message queue used to decouple applications. Instead of one application directly waiting for another application to process something, it places a message into SQS. A consumer processes the message asynchronously. This improves reliability and allows producers and consumers to scale independently.
Producer → SQS Queue → Consumer → Processing → Delete Message

CloudFormation Resources

Resources:

  ApplicationQueue:
    Type: AWS::SQS::Queue

    Properties:

      QueueName: my-application-queue

      # Message remains invisible to other consumers
      # while the current consumer processes it
      VisibilityTimeout: 60

      # Messages can be retained for later processing
      MessageRetentionPeriod: 345600

What happens when a message is submitted?

Application → SendMessage → SQS Queue → Message Stored → Consumer Polls → Message Becomes Invisible → Processing → DeleteMessage

The producer sends a message to SQS. SQS durably stores the message until a consumer retrieves it.

The consumer processes the message and deletes it after successful processing. If processing fails and the visibility timeout expires, the message can become available again.

Important interview concepts

  • Standard Queue – high throughput and at-least-once delivery.
  • FIFO Queue – ordered processing and deduplication features.
  • Visibility Timeout – temporarily hides a message during processing.
  • Dead Letter Queue – stores messages that repeatedly fail processing.

8. Amazon SNS

What is SNS? When is it used?

SNS is a managed publish/subscribe messaging service. A producer publishes a message to an SNS topic, and SNS distributes that message to subscribed endpoints such as SQS, Lambda, HTTP endpoints or other supported destinations.
Publisher → SNS Topic → Multiple Subscribers → SQS / Lambda / Other Consumers

CloudFormation

Resources:

  ApplicationTopic:
    Type: AWS::SNS::Topic

    Properties:
      TopicName: my-application-topic

Runtime Flow

Application Event → Publish SNS Message → SNS Topic → SNS Fan-Out → Subscriber(s) → Processing

SNS is useful when one event needs to be delivered to multiple consumers. For example, one application event can send messages to multiple SQS queues for independent processing.

9. Amazon EventBridge

What is EventBridge? When is it used?

EventBridge is an event routing service. It receives events from AWS services or applications and evaluates them against rules. Matching events are sent to configured targets. It is commonly used for event-driven architectures and scheduled execution.
Event Source → Event Bus → Event Rule → Event Pattern Match → Target → Lambda / SQS / Step Functions / Batch / etc.

CloudFormation

Resources:

  ApplicationEventBus:
    Type: AWS::Events::EventBus

    Properties:
      Name: my-application-bus


  ApplicationRule:
    Type: AWS::Events::Rule

    Properties:

      EventBusName:
        Ref: ApplicationEventBus

      EventPattern:
        source:
          - my.application

        detail-type:
          - ApplicationEvent

      State: ENABLED

      # Target could be Lambda, SQS, Step Functions, etc.
      Targets:
        - Arn:
            Fn::GetAtt:
              - ApplicationFunction
              - Arn

          Id: LambdaTarget

What happens when an event occurs?

AWS/Application → EventBridge → Event Bus → Rule Evaluates Event → Match → Target Invoked

For example, an application publishes an event indicating that a file was processed. EventBridge receives the event and checks its rules.

If the event matches a rule, EventBridge invokes the configured target such as Lambda, SQS or Step Functions.

10. Amazon CloudWatch

What is CloudWatch? When is it used?

CloudWatch is AWS's monitoring and observability service. It collects metrics and logs and can create alarms based on thresholds. It is used to monitor application health, infrastructure behavior, errors, latency, CPU, memory and other operational information.

CloudFormation Resources

Resources:

  ApplicationLogGroup:
    Type: AWS::Logs::LogGroup

    Properties:

      LogGroupName: /application/my-application

      RetentionInDays: 30


  HighErrorAlarm:
    Type: AWS::CloudWatch::Alarm

    Properties:

      AlarmDescription: High application errors

      Namespace: AWS/Lambda

      MetricName: Errors

      Statistic: Sum

      Period: 300

      EvaluationPeriods: 1

      Threshold: 5

      ComparisonOperator: GreaterThanThreshold

      TreatMissingData: notBreaching

What happens at runtime?

Application / AWS Service → Logs / Metrics → CloudWatch → Dashboard / Alarm → Notification / Operational Action

For example, an ECS container writes application logs. The ECS logging configuration sends those logs to CloudWatch Logs.

CloudWatch metrics can also be used to detect abnormal behavior. An alarm can transition state when a configured threshold is exceeded.

11. AWS Batch

What is AWS Batch? When is it used?

AWS Batch is a managed batch-processing service. It is used when work does not need to be handled as a continuously running web application. Examples include large data processing jobs, scheduled processing, scientific workloads and compute-intensive jobs. Batch handles job queues, scheduling and compute capacity.
Submit Job → Job Queue → Scheduler → Compute Environment → Container → Processing → SUCCESS / FAILED

CloudFormation Resources Required

Resource Purpose
ECR Stores the Docker image used by the batch job.
Compute Environment Defines the compute capacity where jobs execute.
Job Queue Holds submitted jobs waiting for execution.
Job Definition Defines container image, CPU, memory, command and runtime settings.
IAM Role Provides permissions required by Batch and the container.
VPC/Subnets/SG Provide networking for the compute resources.
CloudWatch Provides logs and monitoring.

CloudFormation Example

Resources:

  BatchComputeEnvironment:
    Type: AWS::Batch::ComputeEnvironment

    Properties:

      Type: MANAGED

      ComputeResources:

        Type: FARGATE

        MaxvCpus: 16

        Subnets:
          - subnet-12345678

        SecurityGroupIds:
          - sg-12345678


  BatchJobQueue:
    Type: AWS::Batch::JobQueue

    Properties:

      JobQueueName: my-batch-queue

      Priority: 1

      State: ENABLED

      ComputeEnvironmentOrder:

        - Order: 1

          ComputeEnvironment:
            Ref: BatchComputeEnvironment


  BatchJobDefinition:
    Type: AWS::Batch::JobDefinition

    Properties:

      Type: container

      JobDefinitionName: my-batch-job

      PlatformCapabilities:
        - FARGATE

      ContainerProperties:

        Image: 123456789012.dkr.ecr.us-east-1.amazonaws.com/my-batch:latest

        ResourceRequirements:

          - Type: VCPU
            Value: "1"

          - Type: MEMORY
            Value: "2048"

        Command:
          - python
          - application.py

What happens when a job is submitted?

Application → SubmitJob → Job Queue → Batch Scheduler → Compute Environment → Fargate Container → ECR Image Pulled → Job Executes → CloudWatch Logs → Job Status

The application submits a job to the Batch job queue. The Batch scheduler determines when the job can run based on available capacity and scheduling rules.

The compute environment provides the execution capacity. The container image is pulled from ECR and the configured command is executed.

The job eventually reaches a status such as SUCCEEDED or FAILED.

12. Amazon EMR

What is EMR? When is it used?

Amazon EMR is a managed big-data processing platform. It is commonly used for distributed processing frameworks such as Apache Spark and Hadoop. It allows large datasets to be processed across multiple compute nodes.
Data in S3 → EMR Cluster → Spark/Hadoop Processing → Results → S3 / Database

CloudFormation Resources

  • EMR Cluster: Provides the processing environment.
  • EC2 Instances: Provide compute capacity for the cluster.
  • IAM Roles: Allow EMR and EC2 instances to access AWS resources.
  • S3: Stores input and output data.
  • VPC/Subnets: Provide networking.
  • Security Groups: Control network traffic.
  • CloudWatch: Provides monitoring and logs.
Resources:

  EMRCluster:
    Type: AWS::EMR::Cluster

    Properties:

      Name: my-data-processing-cluster

      ReleaseLabel: emr-7.0.0

      Applications:
        - Name: Spark

      Instances:

        MasterInstanceGroup:
          InstanceCount: 1

          InstanceType: m5.xlarge

          InstanceGroupType: MASTER

        CoreInstanceGroup:
          InstanceCount: 2

          InstanceType: m5.xlarge

          InstanceGroupType: CORE

      JobFlowRole: EMR_EC2_DefaultRole

      ServiceRole: EMR_DefaultRole

What happens when a data-processing job runs?

Input Data → S3 → EMR Cluster → Spark/Hadoop → Distributed Processing → Output → S3

The processing framework divides work across cluster nodes. Large datasets can therefore be processed in parallel instead of on one machine.

13. Amazon DynamoDB

What is DynamoDB? When is it used?

DynamoDB is a fully managed NoSQL database. It is commonly used when applications need low-latency key-value or document data storage without managing database servers. Applications interact with DynamoDB through AWS APIs/SDKs.

CloudFormation

Resources:

  ApplicationTable:
    Type: AWS::DynamoDB::Table

    Properties:

      TableName: application-data

      BillingMode: PAY_PER_REQUEST

      AttributeDefinitions:

        - AttributeName: id
          AttributeType: S

      KeySchema:

        - AttributeName: id
          KeyType: HASH

What happens when an application request reads data?

User Request → Application → IAM Authorization → DynamoDB API → Table → Read/Write → Application → User

The application uses the AWS SDK/API to perform operations such as PutItem, GetItem, UpdateItem or Query.

IAM permissions determine whether the application is allowed to perform the requested DynamoDB operation.

14. Amazon S3

What is S3? When is it used?

Amazon S3 is an object storage service. It is used to store files, application artifacts, logs, data files, backups, static content and large datasets. Data is stored as objects inside buckets.

CloudFormation

Resources:

  ApplicationBucket:
    Type: AWS::S3::Bucket

    Properties:

      BucketName: my-application-data

      VersioningConfiguration:
        Status: Enabled

      PublicAccessBlockConfiguration:

        BlockPublicAcls: true

        BlockPublicPolicy: true

        IgnorePublicAcls: true

        RestrictPublicBuckets: true

What happens when a file is uploaded?

Application/User → S3 API → Bucket → Object Stored → Optional S3 Event → Lambda / EventBridge

S3 stores the uploaded object. An event can optionally trigger another AWS service, such as Lambda or EventBridge, for additional processing.

15. AWS Step Functions

What is Step Functions? When is it used?

AWS Step Functions is a workflow orchestration service. It coordinates multiple processing steps and maintains the state of a workflow. A workflow can invoke Lambda, Batch, ECS, DynamoDB and other AWS services. It is useful when an application needs multiple dependent processing steps, retries, error handling and branching.
Start → Step 1 → Step 2 → Decision → Step 3 / Step 4 → Success / Failure

CloudFormation

Resources:

  StepFunctionRole:
    Type: AWS::IAM::Role

    Properties:

      AssumeRolePolicyDocument:

        Version: '2012-10-17'

        Statement:

          - Effect: Allow

            Principal:
              Service:
                - states.amazonaws.com

            Action:
              - sts:AssumeRole


  ApplicationStateMachine:
    Type: AWS::StepFunctions::StateMachine

    Properties:

      StateMachineName: application-workflow

      RoleArn:
        Fn::GetAtt:
          - StepFunctionRole
          - Arn

      DefinitionString: |
        {
          "StartAt": "Process",
          "States": {

            "Process": {
              "Type": "Pass",
              "Result": "Processing started",
              "End": true
            }

          }
        }

What happens when a workflow starts?

StartExecution → Step Functions → State 1 → State 2 → Service Invocation → Next State → Success / Failure

Step Functions maintains the workflow state and moves from one state to the next according to the state-machine definition.

A workflow could, for example, invoke Lambda to validate input, invoke Batch to process data, then write the result to DynamoDB or S3.

16. AWS IAM

What is IAM? When is it used?

IAM controls authentication and authorization in AWS. It determines who or what can access AWS resources and which operations are allowed. In application architectures, IAM roles are especially important because AWS services such as Lambda, ECS and Step Functions assume roles to access other services.
AWS Service → Assume IAM Role → Temporary Credentials → AWS API → IAM Policy Evaluation → Allow / Deny

CloudFormation

Resources:

  ApplicationRole:
    Type: AWS::IAM::Role

    Properties:

      RoleName: application-role

      AssumeRolePolicyDocument:

        Version: '2012-10-17'

        Statement:

          - Effect: Allow

            Principal:
              Service:
                - lambda.amazonaws.com

            Action:
              - sts:AssumeRole

      Policies:

        - PolicyName: ReadApplicationBucket

          PolicyDocument:

            Version: '2012-10-17'

            Statement:

              - Effect: Allow

                Action:
                  - s3:GetObject

                Resource:
                  - arn:aws:s3:::my-application-data/*

What happens when a service accesses another AWS service?

Lambda → Assume Role → Temporary Credentials → S3 API → IAM Policy Check → Allow / Deny
Interview point: Prefer IAM roles and temporary credentials for AWS workloads instead of hard-coding AWS access keys inside application code.

17. AWS VPC and Networking

What is VPC? When is it used?

A VPC provides an isolated network environment for AWS resources. Applications such as ECS/Fargate, Lambda, EMR and other services can use subnets, route tables and security groups to control how network traffic moves between resources and external destinations.
VPC → Subnets → Route Tables → Internet/NAT Gateway → Security Groups → AWS Resources

CloudFormation Resources

Resource Purpose
VPC Creates the isolated network.
Subnet Provides IP address ranges where resources can run.
Route Table Determines where network traffic is sent.
Internet Gateway Provides internet connectivity for resources/routes that use it.
NAT Gateway Allows private-subnet resources to initiate outbound internet connections.
Security Group Controls network traffic to/from supported resources.

CloudFormation Example

Resources:

  ApplicationVPC:
    Type: AWS::EC2::VPC

    Properties:

      CidrBlock: 10.0.0.0/16

      EnableDnsSupport: true

      EnableDnsHostnames: true


  ApplicationSubnet:
    Type: AWS::EC2::Subnet

    Properties:

      VpcId:
        Ref: ApplicationVPC

      CidrBlock: 10.0.1.0/24

      AvailabilityZone: us-east-1a


  ApplicationSecurityGroup:
    Type: AWS::EC2::SecurityGroup

    Properties:

      GroupDescription: Application security group

      VpcId:
        Ref: ApplicationVPC

      SecurityGroupIngress:

        - IpProtocol: tcp
          FromPort: 8080
          ToPort: 8080
          CidrIp: 10.0.0.0/16

What happens when a request reaches the application?

Client → Load Balancer → Network → Route Table → Security Group → Application

The request travels through the AWS networking components. Route tables determine the next network destination, while security groups determine whether the traffic is permitted.

18. AWS CloudFormation

What is CloudFormation? When is it used?

CloudFormation is AWS Infrastructure as Code. Instead of manually creating AWS resources through the console, infrastructure is defined in YAML or JSON templates. CloudFormation creates, updates and deletes resources according to the template and maintains the relationship between resources.
Git → CloudFormation Template → Validate → Create/Update Stack → Dependency Resolution → AWS Resources → Stack Complete

Example resource dependency

VPC → Subnet → Security Group → ECS → Task Definition → ECS Service → ALB

For example, an ECS service needs networking information, a task definition, security groups and subnets. CloudFormation can create these resources and reference outputs from one resource in another.

CloudFormation Interview Concepts

  • Stack
  • Template
  • Parameters
  • Mappings
  • Conditions
  • Resources
  • Outputs
  • Intrinsic functions
  • DependsOn
  • Change Sets
  • Stack Updates
  • Rollback
  • Nested Stacks
  • Drift Detection

19. Terraform vs CloudFormation

Terraform and CloudFormation are both Infrastructure as Code approaches. Terraform uses HashiCorp Configuration Language (HCL) and can manage resources across multiple cloud providers. CloudFormation is AWS-native and uses YAML or JSON to define AWS resources.
Terraform CloudFormation
HCL YAML / JSON
Multi-cloud capable AWS-focused
terraform plan Change Sets / stack updates
terraform apply CloudFormation stack update
Terraform state CloudFormation manages stack state

20. End-to-End AWS Application Example

Scenario

Suppose a customer sends an HTTP request to an application. The application runs on ECS/Fargate, stores information in DynamoDB, places asynchronous work into SQS, and processes that work with Lambda.

Infrastructure Provisioning

Git → UrbanCode Provisioning → CloudFormation → VPC → Subnets → Security Groups → IAM → ECR → ECS → ALB → DynamoDB → SQS → Lambda → CloudWatch

Application Deployment

Code Commit → Build → Test → SonarQube → Fortify → FOSS → Docker Build → Push Image to ECR → ECS Task Definition Revision → ECS Service Update → Fargate Tasks → Health Check

Runtime Request Flow

Customer → DNS → ALB → ECS/Fargate → Application → DynamoDB → Response → Customer

Asynchronous Processing Flow

ECS Application → SQS → Lambda → Processing → DynamoDB / S3 → CloudWatch

Event-Driven Flow

AWS/Application Event → EventBridge → Rule → Lambda / SQS / Step Functions → Processing → CloudWatch

Batch Processing Flow

Application → Submit AWS Batch Job → Job Queue → Scheduler → Compute Environment → ECR Image → Container → Processing → S3 / DynamoDB → CloudWatch

Workflow Orchestration Flow

Application → Step Functions → Lambda → AWS Batch → DynamoDB → Decision → Success / Failure

21. Common Deployment Troubleshooting Flow

Deployment Failed → Check Pipeline Logs → Check AWS Resource Status → Check IAM → Check Network → Check Application Logs → Check CloudWatch → Check Health Checks → Identify Root Cause → Fix → Redeploy

ECS Troubleshooting

  • Check ECS service events.
  • Check stopped task reason.
  • Check ECR image and tag.
  • Check execution role.
  • Check task role.
  • Check subnet and route configuration.
  • Check security groups.
  • Check container port.
  • Check ALB target health.
  • Check CloudWatch logs.

Lambda Troubleshooting

  • Check CloudWatch logs.
  • Check timeout.
  • Check memory configuration.
  • Check IAM permissions.
  • Check event payload.
  • Check environment variables.
  • Check VPC connectivity if Lambda is attached to a VPC.

AWS Batch Troubleshooting

  • Check job status.
  • Check job queue.
  • Check compute environment.
  • Check job definition.
  • Check ECR image.
  • Check CPU and memory requirements.
  • Check IAM permissions.
  • Check CloudWatch logs.

CloudFormation Troubleshooting

  • Validate the template before deployment.
  • Check CloudFormation stack events.
  • Find the first resource that failed.
  • Check IAM permissions.
  • Check resource dependencies.
  • Check parameters and resource names.
  • Check whether the resource already exists.
  • Review rollback information.

22. Simple Interview Explanation

How I would explain the overall approach:

"First, the infrastructure is provisioned as code using CloudFormation. The stack creates the required AWS resources such as networking, IAM, ECR, ECS, load balancing, databases, queues and monitoring."

"Once the infrastructure is ready, the deployment pipeline builds and tests the application, performs code and security scans, creates the application artifact or Docker image, pushes the image to ECR and deploys the application to the appropriate AWS service."

"At runtime, the flow depends on the workload. For a web application, the request can go through DNS and an ALB to ECS/Fargate. For asynchronous work, the application can send messages to SQS. EventBridge can route events to Lambda or other targets, while AWS Batch handles batch jobs and Step Functions orchestrates multi-step workflows. CloudWatch provides logs, metrics and monitoring across the environment."
